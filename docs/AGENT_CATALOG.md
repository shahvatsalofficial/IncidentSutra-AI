# Agent catalogue and necessity review

Twenty roles are portable instructions (Agent Skills), not twenty running models. Each is kept only if it adds a distinct guardrail or procedure. "Backing" shows whether the CLI performs part of the job or the role is guidance only.

| Role | Why it is needed | Backing |
|---|---|---|
| `incidentsutra-prime` | Single entry point that sequences the other roles and enforces that Privacy Guardian and Evidence Ledger can block a handoff. | cli: analyze, verify, audit |
| `incidentsutra-timeline-builder` | Time-zone and precision mistakes are the most common source of wrong incident narratives. | cli: analyze (timeline, quality) |
| `incidentsutra-trace-correlator` | The CLI records trace IDs but deliberately does not join them; this role defines safe joining and sampling caveats. | guidance-only (traceId and spanId are captured by the CLI; joins are manual) |
| `incidentsutra-change-detector` | Deployment proximity is the most over-trusted signal; this role forces the pre-existing-error and unaffected-service checks. | cli: analyze (temporal-correlation, latent-defect hypotheses) |
| `incidentsutra-hypothesis-tester` | Forces falsifiable alternatives instead of one convenient story. | cli: analyze (hypotheses, diagnostics) |
| `incidentsutra-postmortem-writer` | Turns the evidence report into a reviewable document while leaving human-only sections explicit. | cli: analyze (postmortem-draft.md) |
| `incidentsutra-metric-analyst` | Quantifies change from supplied numbers only and refuses to fabricate missing ones. | cli: analyze (metricSeries) |
| `incidentsutra-log-sentinel` | Owns input quality: what was parsed, rejected, skipped or deduplicated. | cli: analyze (ingestionErrors, skippedInputs, duplicatesDropped) |
| `incidentsutra-alert-triage` | Identifies storms and the earliest signal without touching alert configuration. | cli: analyze (alertStorms) |
| `incidentsutra-dependency-map` | The CLI flags dependency language; topology and provider status must come from humans or supplied docs. | guidance-only (the CLI detects dependency wording, not topology) |
| `incidentsutra-blast-radius` | Prevents invented impact numbers by separating observed services from unknown customer scope. | guidance-only (the CLI lists affected services; customer impact needs external data) |
| `incidentsutra-runbook-match` | Classifies runbook steps so a human sees which are read-only and which mutate production. | guidance-only (templates and workflows are provided; matching is manual) |
| `incidentsutra-evidence-ledger` | Mechanical gate: references resolve, nothing is marked confirmed, production checks stay not-run. | cli: verify (digest, references, source re-hash) |
| `incidentsutra-privacy-guardian` | Redaction is best-effort; this role adds a human review step and states the known gaps. | cli: redact, analyze (privacy) |
| `incidentsutra-comms-drafter` | Keeps updates honest about uncertainty and prevents accidental external publication. | guidance-only (drafts text; the CLI sends nothing) |
| `incidentsutra-slo-guardian` | Burn-rate math is only valid with a stated objective and window; this role refuses to guess them. | guidance-only (the CLI exposes raw series; burn-rate math needs supplied targets) |
| `incidentsutra-recovery-planner` | Separates safe diagnostics from mitigation options and keeps both unexecuted. | cli: analyze (diagnostics catalogue, read-only) |
| `incidentsutra-incident-auditor` | Second-look reviewer that reruns the audit and checks wording for overclaims. | cli: audit, benchmark |
| `incidentsutra-ide-bridge` | Installs project-locally without overwriting and records which hosts are tested. | cli: skills list, skills install |
| `incidentsutra-connector-architect` | Live access is a separate security decision; this role specifies guardrails before any code. | guidance-only (no live connector exists; see docs/TOOL_AND_PLUGIN_CATALOG.md) |

**Honest summary.** 13 roles are backed by CLI behaviour; 7 are guidance-only procedures that structure human or host-AI work. Guidance-only roles make no claim of automation. Native activation in each IDE is untested; see `compatibility-matrix.json`.
